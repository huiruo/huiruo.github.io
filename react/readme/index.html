客户端渲染完整流程（不使用 SSR）

在浏览器端，React 的一次更新可概括为 render（协调） 和 commit（提交） 两个阶段。JSX 会先被 Babel、SWC 等编译器转换为 jsx / jsxs 或 React.createElement 调用；组件函数执行这些调用后，返回 React Element。React Element 是对 UI 的轻量描述，常被称为 VDOM，它不是 Fiber，也不是真实 DOM。

text
JSX  -> 编译为创建 React Element 的 JavaScript 调用  -> 执行组件函数，得到 React Element（VDOM）  -> render 阶段：reconcile，将 Element 与 current Fiber 树协调为 workInProgress Fiber 树  -> commit 阶段：将带有 flags 的变更提交到真实 DOM
flowchart TD A[JSX] --> B[编译为 jsx/jsxs 或 React.createElement 调用] B --> C[执行组件 render function] C --> D[React Element / VDOM] D --> E[render: workLoopSync 或 workLoopConcurrent] E --> F[beginWork: 向下协调子节点] F --> G[completeWork: 向上完成 Fiber 并标记变更] G --> H[workInProgress Fiber 树] H --> I[commit: 提交变更] I --> J[真实 DOM、ref、生命周期与 Effect]

render 阶段：将 Element 协调为 Fiber 树

workLoopSync（同步）或 workLoopConcurrent（并发）以深度优先的方式处理工作单元。每个 Fiber 通常先经历 beginWork，再经历 completeWork：

  • beginWork 从上到下比较新旧子节点，执行函数组件或类组件的 render，并为子节点创建或复用 Fiber。常见 Fiber 类型包括 HostRoot（根节点）、FunctionComponent（函数组件）、ClassComponent（类组件）、HostComponent（原生标签）和 HostText（文本）。
  • completeWork 从下到上完成 Fiber：首次挂载时为 HostComponent、HostText 准备 DOM 实例并组装子节点；更新时计算属性或文本的更新内容，并把插入、更新、删除等变更记录为 Fiber flags。此时仍在内存中准备工作，尚未把变更写入页面。

render 阶段的产物是新的 workInProgress Fiber 树及其变更标记；在并发渲染中，这一阶段可以被更高优先级的更新打断并重做。

commit 阶段：把变更写入页面

当 render 完成后，commit 阶段同步且不可中断地遍历带有变更标记的 Fiber，将结果应用到宿主环境（浏览器中即 DOM）。它主要包括：

  1. beforeMutation：DOM 变更前的准备工作，例如读取 getSnapshotBeforeUpdate。
  2. mutation：执行真实 DOM 的插入、删除、文本和属性更新，并处理 ref 的解绑。
  3. layout：绑定 ref，调用类组件生命周期（如 componentDidMount、componentDidUpdate）和 useLayoutEffect；随后 React 调度被动 Effect，执行 useEffect 的清理与回调。

因此，React 的核心路径是：组件函数返回 React Element，render 阶段把它协调为带变更标记的 Fiber 树，commit 阶段才把这些变更提交到真实 DOM 并触发 ref、生命周期和 Effect。

vue 和 react 异同

以下比较以 React 19 和 Vue 3 为基线。两者都能构建相同类型的 Web 应用，主要区别不在“能不能实现”，而在状态如何被感知、更新工作如何被组织，以及框架把多少约束交给编译器或开发者。

共同点

  1. 声明式、数据驱动 UI：开发者描述“当前状态对应什么 UI”，状态变化后由框架计算并提交必要的 DOM 更新，而不是手动维护每一个 DOM 操作。
  2. 组件化与单向数据流：都通过 props 将数据从父组件传向子组件，通过事件或回调把用户意图向上传递。组件都可以拆分为展示组件、业务组件以及可复用逻辑。
  3. 虚拟 DOM：React Element 和 Vue VNode 都是 UI 的轻量 JavaScript 描述。两次渲染结果经过 reconciliation / patch 后，框架只把必要变化提交到真实 DOM。
  4. 状态、派生值与副作用：两者都区分组件状态、由状态计算出的值和需要与外部系统同步的副作用，只是 API 和依赖追踪方式不同。
  5. 工程能力：都支持 TypeScript、路由、状态管理、SSR、流式渲染、Hydration、测试和跨端生态，通常需要配合对应框架或工具链完成完整应用架构。

核心差异

维度React 19Vue 3
定位与设计更接近 UI 运行库，强调 JavaScript 组合能力；路由、状态管理和项目结构有较大选择空间。渐进式框架，官方提供模板、响应式系统以及 Router、Pinia 等相对统一的配套方案。
UI 描述主要使用 JSX，把标签、表达式和控制流放在 JavaScript 中组合。默认使用更接近 HTML 的 SFC Template，也支持 JSX 和手写 render function。
编译优化JSX 可被 Babel、SWC 等工具分析和转换；启用 React Compiler 后，还可以自动缓存组件输出、值和函数，减少手写 memo、useMemo、useCallback。模板语法约束更强，编译器可提前生成静态提升、Patch Flag、Block Tree 和动态节点列表，让运行时跳过已知的静态部分。
响应式模型不代理普通变量的读写。调用 state setter 后，React 把更新加入队列，再执行相关组件函数，根据新旧渲染结果协调更新。reactive 通过 Proxy、ref 通过 getter/setter 拦截读写；组件渲染时执行 track 收集依赖，数据修改时通过 trigger 通知订阅它的响应式 Effect。
状态更新习惯state 应按不可变数据处理，通过 setState 或 useState setter 提交新值；setter 表示“请求一次更新”，读取到的仍是当前渲染快照。响应式对象通常直接修改，ref 通过 .value 修改；Proxy / getter/setter 会捕获操作并触发依赖更新。
默认更新粒度某组件 state 更新后，React 默认重新执行该组件，并递归处理它返回的子组件；最终只提交有差异的 DOM。组件只订阅渲染过程中实际读取的响应式数据；依赖变化时，通常只把订阅该依赖的组件更新任务加入队列。
避免无效渲染可使用合理的组件边界、稳定 props、React.memo，或启用 React Compiler。依赖追踪先缩小需要更新的组件范围，模板编译信息再帮助运行时只遍历动态节点。
调度与批处理Fiber 将渲染工作拆成工作单元，并用优先级和 Lane 组织更新；并发渲染可以暂停、恢复或放弃尚未提交的 Render，但 Commit 仍是同步完成的。状态修改后通常不会立即更新 DOM，而是把去重后的组件任务放入调度队列，在 next tick 统一刷新；可用 nextTick 等待 DOM 提交完成。
列表协调依据元素类型、位置和 key 复用节点；Fiber 子节点协调会标记插入、移动和删除，再在 Commit 阶段操作 DOM。同样依据类型和 key 复用节点；Vue 3 的 keyed children patch 会处理公共首尾区间，并在未知序列中借助 key 映射和最长递增子序列减少移动。
复用逻辑以函数组合为中心，主要通过自定义 Hook、普通函数、组件和 Context 复用。主要通过 Composition API composable、组件、指令以及 provide / inject 复用。
副作用useEffect 显式声明依赖数组；Effect 以 setup / cleanup 的方式与外部系统同步。watchEffect 自动收集同步执行期间读取的响应式依赖；watch 显式指定数据源，并可控制执行时机。

渲染和更新原理

React：显式触发更新，按组件树协调

text
事件或异步结果  → 调用 state setter  → 更新进入队列并被调度  → Render：执行相关组件，构建新的 React Element / Fiber 工作树  → Reconciliation：依据 type、key、位置标记变化  → Commit：一次性提交 DOM、ref 和布局 Effect  → 浏览器绘制后执行普通 Effect

React 的 Render 阶段是纯计算。在并发渲染中，这一阶段可以被高优先级任务打断、恢复或丢弃；只有完成的结果才会进入 Commit，因此不能把“可中断渲染”理解成 DOM 被更新了一半。

React 默认会处理更新组件的后代。React.memo(Component) 默认使用 Object.is 对每个 prop 做浅比较；props 未变化时可以跳过该组件。自定义比较函数返回 true 表示新旧 props 相等、跳过渲染，返回 false 表示需要重新渲染。类组件的 shouldComponentUpdate 语义与之相反：返回 true 表示继续更新，返回 false 表示跳过。

Vue：自动追踪依赖，按响应式 Effect 触发更新

text
渲染函数读取 reactive / ref  → track：记录“响应式属性 → 组件渲染 Effect”的依赖  → 修改响应式状态  → trigger：找到订阅该属性的 Effect  → 更新任务去重后进入调度队列  → 重新执行目标组件的 render function，生成新 VNode  → Patch：结合 key、Patch Flag 和 Block Tree 比较动态部分  → 提交必要的 DOM 更新

Vue 的依赖追踪类似于自动确定“哪些组件依赖了这份数据”，但它不等同于为每个组件自动执行 shouldComponentUpdate：前者在属性读取层面建立订阅关系，后者是在 React 已经准备更新组件时决定是否跳过该组件。

容易混淆的概念

概念层级ReactVue
UI 的虚拟描述React ElementVNode
当前组件树的运行时内部结构Fiber Tree；节点还保存 state、更新队列、优先级以及父子兄弟关系组件实例树及其 SubTree / VNode Tree
什么变化会触发组件工作setter 显式提交更新，React 从相关 Fiber 开始调度Proxy / ref 的 track、trigger 建立并触发响应式依赖图

因此，“Vue VNode 对应 React Fiber”并不准确：Vue VNode 更接近 React Element；Fiber 除了关联 UI 描述，还承担可调度工作单元和组件运行时状态等职责。响应式依赖图则解决“谁依赖了这份状态”的问题，也不是虚拟 DOM 树。

Diff 与性能应如何理解

  • 两者都依赖稳定且唯一的 key 判断列表项身份。使用数组下标或随机值作为 key，都可能导致错误复用、状态丢失或额外 DOM 操作。
  • Vue 的优势之一是模板编译器能给运行时更明确的更新提示；React 的优势之一是 Fiber 调度模型能够区分优先级，并支持并发 Render。React Compiler 启用后也会在构建阶段自动加入细粒度缓存。
  • “Vue 一定更快”或“React Fiber 一定更快”都不是可靠结论。实际性能取决于组件边界、状态位置、列表 key、更新频率、编译配置和业务场景，应通过 Profiler 和真实指标判断。
  • Vue 2、React 15 的实现可用于理解历史演进，但不能直接代表 Vue 3 和 React 19。Vue 3 会批量调度 DOM 更新；React 的可中断部分是并发 Render，而不是 Commit。

选型参考

  • 偏向 React：团队希望用 JavaScript / TypeScript 统一表达 UI 与逻辑，需要更自由地组合路由、状态和渲染方案，或依赖庞大的 React、React Native 及框架生态。
  • 偏向 Vue：团队希望模板、样式、逻辑边界清晰，重视渐进式接入、官方配套和较低的上手成本，并希望默认获得响应式依赖追踪和模板编译优化。
  • 不要仅按知名产品选型：React 和 Vue 都有大型生产案例。Notion、Figma、X 等产品可以说明 React 生态成熟，但不能证明某个具体项目天然更适合 React；应结合团队经验、已有代码、SSR 方案、性能目标和长期维护成本选择。

二.两大阶段:render 和 commit

二-A.render构建fiber树:beginWork阶段和completeWork阶段

render 阶段是在内存中构建一棵新的 fiber 树（称为 workInProgress 树）,构建过程是依照现有 fiber 树（current 树）从 root 开始深度优先遍历再回溯到 root 的过程，这个过程中每个 fiber 节点都会经历两个阶段：beginWork 和 completeWork。

workLoopSync 负责以递归方式调用 performUnitOfWork，从根组件开始一直到叶子组件，然后再返回到根组件，直到整个组件树中没有工作单元需要处理

基础1-构建fiber 遍历流程

遍历流程

Tree 构建的遍历顺序，它会以旧的fiber tree为蓝本，把每个fiber作为一个工作单元，自顶向下逐节点构造workInProgress tree（构建中的新fiber tree）:

深度优先遍历

  1. 从顶点开始遍历
  2. 如果有子节点，先遍历子节点；
  3. 如果没有子节点，则看有没有兄弟节点，有则遍历兄弟节点，并把effect向上归并
  4. 如果没有兄弟节点，则看有没有父兄弟节点，有则遍历父兄弟节点
  5. 如果没有都没有了，那么遍历结束

在 render 阶段，一个庞大的更新任务被分解为了一个个的工作单元，这些工作单元有着不同的优先级，React 可以根据优先级的高低去实现工作单元的打断和恢复。

异步可中断更新，在构建 workInProgress 的过程中，如果有更高优先级的更新产生， React 会停止 workInProgress fiber tree 的构建，然后开始处理更高优先级的更新，重新构建 workInProgress fiber tree。

等更高优先级的更新处理完毕之后，才会处理原来被中断的更新。

React fiber 的构建的过程以每个 fiber 作为一个工作单元，进行工作循环，工作循环中每次处理一个任务（工作单元），处理完毕有一次喘息的机会：

while (nextUnitOfWork !== null && !shouldYieldToRenderer()) {  nextUnitOfWork = performUnitOfWork(nextUnitOfWork);}

2.commit 阶段分为3个阶段

在 render 阶段结束后，会进入 commit 阶段，该阶段不可中断,commit 阶段的调度优先级采用的是最高优先级，以保证 commit 阶段同步执行不可被打断。

相应的节点进行提交，渲染到页面上,在 commit 阶段就会操作真实节点，将它们插入到 dom 树中:

2-1.Before mutation 阶段（执行 DOM 操作前）；

  • 对于类组件，执行 getSnapshotBeforeUpdate 生命周期
  • 对于函数组件，异步调用 useEffect

2-2.mutation 阶段（执行 DOM 操作）；

  • 进行真实的 DOM 操作

2-3.layout 阶段（执行 DOM 操作后）

  • 对于类组件，会执行 setState 的 callback
  • 对于函数组件，会执行 useLayoutEffect

主要是去依据 workInProgress 树中有变化的那些节点（render 阶段的 completeWork 过程收集到的 effect 链表）,去完成 DOM 操作，将更新应用到页面上，除此之外，还会异步调度 useEffect 以及同步执行 useLayoutEffect。

子组件的useEffect先走

解析：按照这个执行逻辑来看的话：

  • 父组件进入commit阶段，发现有子组件组件需要渲染。

  • 开始进行子组件的生命周期, 子组件进入commit阶段，执行子组件的useEffect，子组件渲染结束

  • 父组件进行commit阶段，渲染完成，执行useEffect

react 父组件子组件的渲染先后顺序和深度优先搜索

父组件和子组件的渲染顺序通常遵循深度优先搜索（DFS）的原则。

深度优先搜索是一种遍历树结构的算法，它首先沿着树的深度尽可能远的分支向下遍历，然后返回并探索未遍历的分支。在React中，组件树也可以视为一个树结构，其中每个组件可以有多个子组件。

当React应用加载时，首先会渲染根组件(最顶层组件),然后React会递归地渲染子组件，直到整个组件树被遍历完。这个过程遵循深度优先搜索的原则，即React会首先渲染当前组件的一个子组件，然后再继续渲染这个子组件的子组件，以此类推，直到所有子组件都被渲染完。

子组件的componentDidMount先执行,父组件的后执行

正确的渲染顺序如下：

text

D.react17-18对比

B-1.setState自动批处理

  • 在React17默认情况下，在promise、setTimeout、原生事件处理函数中、或任何其它事件内的更新都不会进行批处理。

  • 在React18以后,所有更新都会自动进行批处理。多次更新将会合并成一次更新，从而降低渲染次数提高性能。

js
// 退出批处理，需要使用flushSyncimport React, { useState } from 'react';import { flushSync } from 'react-dom';
const App: React.FC = () => {  const [count1, setCount1] = useState(0);  const [count2, setCount2] = useState(0);  return (    <div      onClick={() => {        flushSync(() => {          setCount1(count => count + 1);        });        // 第一次更新        flushSync(() => {          setCount2(count => count + 1);        });        // 第二次更新      }}    >      <div>count1： {count1}</div>      <div>count2： {count2}</div>    </div>  );};
export default App;

在React18中提供了新的root Api，我们只需要把render改成ReactDOM.createRoot(root).render(<App />)就可以开启并发模式。 并发特性是开启并发模式才能使用的特性:

  • startTranstion
  • useTranstion
  • useDeferredValue

在视图更新的时startTransition 能够保持页面有响应，这个 api 能够把 React 更新标记成一个特殊的更新类型 transitions ，在这种特殊的更新下，React 能够保持视觉反馈和浏览器的正常响应。

  1. startTransition: startTransition(scope)

scope 是一个回调函数，里面的更新任务都会被标记成过渡更新任务，过渡更新任务在渲染并发场景下，会被降级更新优先级，中断更新。

  1. useTranstion 在低优先级还没执行的时候，怎么知道过渡任务处于什么状态，这时候就可以使用useTranstion这个Hooks。useTranstion执行返回一个数组，数组有两个状态值。

  1. useDeferredValue 返回一个延时响应的值可以让一个state延时生效，只有当前没有紧急更新的任务时，该值才会变为最新的值。和startttanstion一样都是标记为非紧急更新。

useTranstion和useDeferredValue异同： 相同点： useDeferredValue本质上和内部实现与useTranstion一样都是标记成了过度更新任务。

不同点：useTranstion是把startTranstion内部的更新任务变成了过度任务transtion，而useDeferredValue是把原值通过过度任务得到新的值，这个值作为延时状态，一个是处理逻辑，一个是生产一个新的状态。

其他：为什么React 18 的组件定义要大写

Sat Mar 23 18:44:58 CST 2024

在React中，组件定义要求组件名称必须以大写字母开头。这是为了让React能够区分组件和HTML标签。

在JSX中，如果你使用小写字母开头定义一个组件，比如 <myComponent />，React会将它视为HTML标签而不是React组件。而如果你使用大写字母开头定义一个组件，比如<MyComponent />，React会将它视为一个自定义的React组件。

这个约定有助于提高代码的可读性，并且使得开发者能够清楚地区分哪些是React组件，哪些是HTML标签。
